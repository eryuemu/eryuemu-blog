> 最近在玩小 e 社（Escu:de）的《悠刻的命运少女》，顺便折腾了一下 AI 汉化与 Agent 自动重译，深夜调试有感。

---

## 1. 游戏背景与已有 AI 翻译版本

最近在玩小 e 社（Escu:de）的 Galgame **《悠刻的命运少女》**。

目前市面上能找到的汉化资源基本都是 AI 机器翻译的版本，主要分为三个主流版本：

1. **GPT-4o 翻译版**
2. **Claude 3.5 Sonnet 翻译版**
3. 另一个未知 AI 模型翻译的版本

![《悠刻的命运少女》游戏翻译版本与运行画面](../../assets/yukoku-img-1.jpg)

不得不感慨大模型技术迭代之快，在如今 GPT-5.6 / Gemini 3.6 Flash / DeepSeek-v4 Flash 纷纷问世的今天，GPT-4o 和 Claude 3.5 Sonnet 在当下看居然已经算得上是“相对老旧的模型”了。

### 实际阅读体验与痛点

* **GPT-4o 版**：下载拿到的资源默认就是 GPT-4o 翻译的。实际阅读体验非常令人不满意，生硬的机翻感比较浓，语病和文本错漏不少，经常让人出戏。
* **Claude 3.5 Sonnet 版**：抱着试一试的心态换成了 Claude 版本，但这版是繁体中文，阅读起来相当吃力，排版与习惯用词也比较麻烦，看了一会儿眼花缭乱，最终还是放弃了这个版本。

---

## 2. 动手：尝试用 AI Agent 自己优化/重译汉化

既然平时就比较爱捣鼓技术和各种 AI 工具，面对不尽如人意的机翻文本，第一反应自然是：**能不能用 AI Agent 搭建个自动化工作流，自己来优化或者重新润色一版翻译？**

说干就干，开始动手折腾。

### 第一回合：Antigravity + Gemini 3.6 Flash

最初尝试使用 Antigravity 搭配 **Gemini 3.6 Flash** 模型来处理汉化文本解析与润色脚本。

搞了一顿之后最终还是换掉了：Gemini 在处理复杂代码逻辑、脚本结构化提取以及自动化逆向工具调用时的代码能力确实有点拉胯，经常在关键逻辑上出错或陷入无效循环。

### 第二回合：Claude Code CLI + DeepSeek-v4 Flash

果断切换到了平时更熟悉的 **Claude Code CLI** 搭配 **DeepSeek-v4 Flash** 模型。

![Claude Code CLI 终端调试与工作流](../../assets/yukoku-img-2.jpg)

这里不得不夸一句：**Flash 系列模型的性价比是真的高！** 跑大批量文本润色和频繁的代码交互，成本和速度优势极其明显。

## 3. 深夜调试拉锯战与真实感悟

本以为写个 Prompt 和处理脚本很快就能搞定，结果从晚上 **8:50** 一直反反复复调试到了深夜 **2:00**，整整折腾了五六个小时，前后迭代了几十轮。

在这个过程中，有两点感受特别深刻：

### 1. 工具体验：VS Code 插件 vs 终端 CLI
在调试过程中顺带对比了一下：**VS Code 里的 Claude Code 插件体验感觉还是明显不如终端 Terminal CLI**。CLI 终端操作更加直接、反馈更清晰，而在 IDE 插件里有些交互和上下文感知反而显得拘束。

### 2. “自然语言编程”的幻觉陷阱
这次最大的感悟就是：**单纯依靠自然语言编程是完全不可行的。**

在缺乏对底层数据结构、引擎字符编码以及文本替换逻辑精准控制的情况下，直接交给 Agent 去凭空生成和处理，感觉自己就好比“文科生用 AI”——**人类自己的“幻觉”甚至比 AI 的幻觉还要高！** 总是以为一两句话 AI 就能完美搞定底层所有的机制，结果现实中各种编码错乱、文本截断和排版崩坏频发。

```
自然语言 Prompt ──→ 人类幻觉高涨 ("AI 肯定能搞定")
                        │
                        ▼
Agent 自动执行 ──→ 编码错乱 / 结构崩溃 / 校验失败
                        │
                        ▼
深夜 02:00 ──→ 人类理性回归 ("还是得懂底层原理")
```

---

## 4. 摆烂与总结：术业有专攻

折腾到深夜 2 点，眼看时间不早了，最终还是选择放弃——**暂时先用 GPT-4o 的版本看吧，实在懒得继续搞其他版本了。**

![前几天《戦巫〈センナギ〉》脚本解包逆向与逻辑修改实战](../../assets/yukoku-img-3.jpg)

这也让我想起前几天玩小 e 社的前作《戦巫〈センナギ〉》时的经历：当时为了解锁神気率 100% 的好结局，先是用 Claude Code 先后尝试修改二进制 Saver 存档和实时内存扫描，结果都因为数据校验和动态偏移拦截失败；最后还是通过解包游戏脚本，逆向 YU-RIS VM 字节码并修改脚本逻辑重打包才成功解锁。

只能说：**在汉化润色、文本提取和游戏逆向这方面，终究还是“术业有专攻”**。

AI 大模型确实是极其强大的效率工具，但它并不能完全替代对底层游戏引擎机制、编码转换和文本上下文的深入理解。要想做出真正优秀高质量的汉化或逆向修改，人类的专业经验与 Agent 的算力辅助缺一不可。
